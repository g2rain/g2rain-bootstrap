# 差异与风险

## 已确认差异

- 中央 G2rain 目录已登记本项目为生产部署入口，但未发布部署编排类正式 Profile，当前使用[本地基线](local-baseline.md)。默认最低资源验证预设不代表生产容量基线。
- 与 [g2rain-deploy](https://github.com/g2rain/g2rain-deploy) 相比：无源码构建映射、无 Compose V1 并行栈、无 `init-once.sh`、无按服务名更新；`--business` 为追加语义，不是“仅加载列出片段”。
- `g2rain-admin-shell` 内置于基础编排，而不是独立业务片段。
- 业务片段全部由配置选择；脚本不写死默认扩展。CMS 启用前需确认 GHCR 镜像可拉取。
- `.env.example` 含固定的数据库、Redis、Nacos、Milvus 示例凭据；生产环境直接沿用会形成安全风险。
- Git 当前跟踪多个 `config/g2rain-*/keys/` 下命名为私钥的 PEM/DER 文件。它们必须视为不可信的演示材料。
- 默认资源档为单请求 Demo 最低配置，冷启动与文档解析会较慢，不适合并发或生产。
- 中央目录列有按目标生成部署方案的职责，但当前脚本只提供固定编排生命周期入口，未见独立方案生成命令；该职责的交付范围仍需后续需求明确。
- 2026-11-08 以 Git for Windows Bash 复核，`config/generate_key.sh` 语法检查通过，替代 2026-11-07 的历史失败记录；未执行实际密钥生成或验证轮换流程。

## 未验证项

- 未实际启动容器或验证健康检查、端口、服务发现、登录及前端访问。
- 未验证真实安装、更新、停止、备份或回滚流程。
- 未验证 Linux 发行版、文件权限、SELinux、防火墙和生产 Docker/Compose 版本兼容性。
- 未验证数据卷升级、数据库重复初始化和跨版本迁移。
- 未验证 Docling HF 模型预置、离线模式与镜像派生构建在目标主机上的端到端结果。
