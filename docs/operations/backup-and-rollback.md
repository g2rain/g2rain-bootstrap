# 备份与回滚

仓库脚本未形成经过验证的完整灾难恢复方案。生产或共享演示环境变更前至少保存：

- MySQL 一致性备份及恢复验证记录（命名卷 `mysql-data`）
- Redis、Nacos、Kafka 所需的持久化数据或可重建说明
- `data/milvus/`（向量数据、嵌入式 etcd、本地 WAL 与建表标记）
- `data/g2rain-knowledge/`（知识原文件与解析产物）
- `data/docling-hf/` 或实际 `DOCLING_HF_CACHE`（若依赖离线模型）
- 当前 `.env`、Compose 片段、Nginx 与中间件配置的安全副本
- 当前镜像 digest 与组件版本标签
- 应用密钥与证书的安全备份及轮换计划；Nacos 内数据源/Redis 凭据必须与 `.env` 一并备份

回滚应优先恢复已记录的镜像 digest 与配置，再按依赖顺序重建服务。数据库架构或数据发生不可逆迁移时，容器版本回退并不等同于系统回滚。

任何声称“可回滚”的发布，都应在非生产环境实际演练并记录恢复时间和数据一致性结果。
